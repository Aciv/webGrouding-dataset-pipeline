# v12：深层逐级补入第四层，细节归档第五层

本版保留 v11 的严格补缺，但将融合移到最终归档之前；替代 v9 的严格按类别/像素面积删除。必须从原始 datasets 的 hierarchy 重新处理，不能把已经严格删过的派生树当作完整输入。
不修改采集器、截图或源数据，不新增 DOM 观测。

## 1. 主树四层，历史细节单独保留

- nodes 是 L1–L4 主树，parent 与深度严格一致，分支可提前结束。
- detail_archive.nodes 是视觉上归入第五层的细节档案，默认不训练。
- 归档保留 bbox、类别、原 parent、原层级、原因及 owner_id，不是删除。
- owner_id 是与主框的关联，可以指向 L1–L4；归档不强行构造假的四层父节点，不伪造训练 parent 边。
- 原始 L5+ 框必须在主树或第五层档案中可找到。预处理收缩掉的深层包装也进入档案。
- 将来若要训练归档层，需明确其监督和归属协议；不能直接把归档数组拼到主树当成 parent 深度一致的训练树。

```json
{
  "nodes": [{"node_id":"main_id","layer":3,"parent_id":"level3_id","bbox":[0,0,100,40]}],
  "detail_archive": {
    "display_level": 5,
    "excluded_from_training_by_default": true,
    "nodes": [{"node_id":"detail_id","bbox":[4,4,8,8],"owner_id":"main_id",
      "original_level":7,"original_parent_id":"old_id","archive_reason":"already_represented_by_l4_object"}]
  }
}
```

## 2. 从最后一层往前累计，补缺而非全部堆入

先复用几何规范化与包装收缩，关闭 v9 的严格删除；再收集 L4 之后的候选；保留现有 L4 前沿，按覆盖关系、尺寸和新增前沿筛选。

- 同一视觉对象已有 L4 框：内部小字、图标不再单独补入，归档第五层。
- 同父现有 L4 框覆盖候选面积至少 95% 时，不论现有框是否为普通 block，候选都留在 L5。此为分层粒度政策，不声称功能相同。现有 L4 包含关系优先于小框判定。
- 近乎同框的源包装和对象只留一个主代表，优先具体对象；其他记录归档。
- 单图 figure 与对应图片可复用更准确的图片框作 L4 代表，避免两个重叠框；figure 原框进入档案。
- 仅不被现有 L4 覆盖、尺寸有效的候选可补入。按原始层级从浅到深、同深按面积从大到小选取前沿；与已选新增框相互包含达到 95% 的候选留在 L5，避免包装与内部细节变成同层兄弟。补入时原 bbox 不变。
- 近同框或单图 figure 的准确代表替换仍可发生，单独计为 replaced_existing_l4，不计为补缺。
- 原有 L4 过粗时应走已有的模型验证上层替换机制，不在补缺阶段自动拆解；本次不以放宽补缺代替语义判断。
- 不因为是 text、link、image 就批量删除。

先前已存在的 L4 框不只因频率惩罚就被移除；频率/小尺寸门槛主要决定深层补充候选是否进入主树。

## 3. 过小同时检查面积、宽度和高度

参考宽度为截图宽；参考高度为 min(截图高, 1.5 × 截图宽)，避免长图把正常矮控件误判成微小物体。这是比例归一化参考，不是推测浏览器 viewport。

默认基础门槛：面积比 <0.0001，宽度比 <0.03，高度比 <0.03，三项必须同时满足。
宽而薄、窄而长的框不会仅因面积小被归档。

## 4. 数量按相近宽高累计，跨类别

- 宽与高都相近才算同组；默认组内两端最大/最小比例均不超过 1.25。
- 不按 tag/struct 分类，文字、图片、按钮可在同一尺寸组。
- 不使用单链串联，避免尺寸逐渐变大却被串成一组。
- 同位置、同框的重复包装不重复计数。
- 每组 20 个以内惩罚系数 P=1；超过后 P=min(4, 1+(数量−20)/20)。
- 面积门槛乘 P²；宽高门槛乘 P，但最多放宽到 0.08，防止宽标题/长条框被频率误伤。
- 惩罚只影响比例上足够小的补充对象，不能因为大卡片很多就把它们当小噪声。
- 计数在过滤前固定一次，避免移入档案后反复改变惩罚，产生顺序依赖或振荡。

每份报告记录尺寸组成员、计数、P、有效门槛；每个被判过小的归档记录实际比例。

## 5. 第四层拥挤后才考虑聚合或上层拆解

以下仅触发规则候选，不直接执行：

- 同父元素数量至少 16；或
- 互相覆盖较多的框对占比至少 20%（相交覆盖较小框 80% 计为一对）；或
- 上层同级区域数量少于 2，但内部至少有 4 个框。

优先复用已有的下层容器框，把它提升为上层区域，接收相应 L4 内容；不新增同框包装。
如果不能复用，聚合下层后，新区域与旧上层同级，旧上层只保留剩余内容并收缩。
原有主树成员不能因此加深。空的旧包装被收缩替换，不把整片前景错误写为 ignore。

模型判断的是固定候选是否合理；可拒绝或不修改。最终第五层档案不参与再聚合；但在形成归档之前，完整规范化树的 L5+ 候选可以参与融合，不能提前从模型输入中排除。详见 FUSION_BEFORE_ARCHIVE.md。
像素回退继续用于子块方法拆不开的大框，仍须明确批准固定分区。

## 6. 模块与查看

- layer_accumulation.py：累计补缺、对象对应、比例与尺寸频次、第五层档案、密度诊断。
- replacement_groups.py：提升已有下层代表或拆解上层，不额外加层。
- grouping.py：只在密度/覆盖条件触发时提出候选。
- grouping_pipeline.py：默认 v10；训练主树与非训练归档明确分开。
- compare.py：L1–4 看主体，勾选 L5 看归档；提示框显示 owner，而非伪装成训练 parent。

参数位于 config.example.json 的 accumulation。私有 API 配置无需覆盖，新字段有默认值。
旧 v9 投票不可直接复用为 v10 批准，因为候选和输入内容已经改变。

这些都是未验证的规则候选，不宣称等同人工真值；结构合法不代表语义正确。
