# 框整理、切片与训练交接计划

状态：目标设计。2026-11-07离线处理、切片、索引和统计已通过 `../offline_postprocess/` 落地；训练器接入和切线网络训练尚未实施。2026-11-06按实际样本和用户最新约束修订。

## 1. 目标与顺序

```text
原始索引 → 任务范围预筛（极端密集表格整页排除）→ 视口预筛 → 小框清理/融合 → 大框清理/分解
→ 锁定整页对象与关系 → H>2700时DCGen+框布局长度切片
→ 切线/可见性微调 → 最终质量检查与发布
→ 宽度分桶探测、统一检测训练、整页验证
```

不强制五层，不依赖VLM。主规则见../layer_postprocess/PLAN.md，样本证据见../layer_postprocess/SPECIAL_SAMPLES.md，质量筛选见../page_filter/PLAN.md。

## 2. 数据与产物

v13派生标签已废弃，禁止作为输入或复用缓存。当前datasets已有3957个原始候选视口，直接使用其hierarchy；原图、原标签只读。

索引明确引用稳定整页标签、质量状态、裁图清单、最终切线标签及审计日志。每条记录带page/viewport、版本、源指纹、配置指纹。版本和指纹一致才恢复缓存；不复用旧VLM批准记录。

框操作阶段允许在有证据时调整派生结构；切片阶段只创建视图。保留global_node_id、全局parent引用与局部坐标变换，片外父节点不导致子节点提升到root。检测资格和结构关系独立。

## 3. 配置与分割模型

后处理使用一个YAML：质量、框清理、DCGen参数、切片、日志和资源预算分章节。split/probe/train/validate各自配置引用同一派生索引；显式CLI才覆盖配置。

H≤2700保留整图，H>2700切成900–1800实际裁片。宽度分桶在训练端统一实现；不要将1800误用为所有输入上限。

分割模型输入等比缩小的完整原图，输出最终全宽水平切线y/H。原图首尾不预测；模型不学习DOM层级、框分解过程、父子树或微调历史。尺寸、padding和有效范围明确记录；预测线还原后在原分辨率裁图。

标签辅助离线生成最终切线；真实框不进入预测输入或验证解码。预测候选经高度约束解码，回退仅用像素/尺寸并显式记录。普通H≤2700页面为空线；失败/待审样本不得当成空线负例。

## 4. 检测训练接入

- 全框head监督内容块/组件及显著元素；小文字、小链接、单元格细节由聚合代表承接后取消独立监督。取消按max_depth=4/5筛目标，不新增分层head。
- 分割线生成可使用保留的细粒度几何证据，但检测目标只取detection_eligible=true。被吸收对象不进入匹配、损失、384容量计数或检测GT；来源对象和结构图另存。
- represented_by_content_group/drop_fine_grained_noise属于已确认目标粒度，不自动转ignore；残缺/未知/缺失标注才使用ignore。报告内容代表覆盖和显著对象误删，不以保留全部原子框为目标。
- 保留DOM语义与结构图，训练不因过滤structure_only改变对象身份或语义层级。
- 超大无法容纳对象按明确协议排除其完整框监督；已有内部对象继续使用，不增加整页概览补测路径。
- 切片不变更类别、父子关系或完整框，不按局部比例重新定义有效目标。
- 实现边缘残缺与不完整标注的ignore匹配/损失处理；不能仅写字段但损失不消费，也不能将大背景ignore无差别覆盖其有效子对象。
- 停用与新数据政策冲突的重复融合、旧低layer优先截断；>384先尝试合规切片，仍失败记录冲突。
- probe/train/validate共享裁图与变换；按宽度分桶，批大小只是上限。
- 对无法适配新语义的旧递归路由明确不支持，不能用压缩树冒充完整关系。

## 5. 划分与评估

先按原页面/站点划分再展开视口、裁图和分割标签，所有派生版本共用归属。检测仍每5epoch验证固定同一批64个原始页面，不改成64张裁图。

验证使用纯像素基线或已训练切线模型；GT辅助裁图只能另列诊断。映射预测到原图后处理跨裁片重复，明确归属策略并保存融合记录。

分割评估原图坐标的一对一容差命中、位置/数量误差、切断率、回退率、触发门槛与裁片高度符合率。检测评估说明清理/超大对象排除后的目标协议，并报告目标保留比例，不能仅凭删难目标后的AP宣称提升。

## 6. 发布门槛

先复核SPECIAL_SAMPLES所列极端与正常样本，落实可复现规则，再小规模端到端试跑。覆盖2700/2701触发边界、超大背景、密集表格容量、片外父引用、地图错位及局部残缺。记录每原页面训练成本、宽度分桶填充和重叠样本数。

离线代码和本地datasets处理已完成，真实运行证据见 `../offline_postprocess/RUN_EVIDENCE.md`。本次没有启动切线网络或检测训练。

## 7. 极端表格排除的交接

任务范围预筛先于框聚合和长度切片。已确认的极端密集表格页按原page_id标记out_of_scope_dense_table，所有视口、切片、检测GT和分割线标签均不进入训练/验证发布索引；不误当空切线负例。不删除源图或标签，也不排除同站点其他正常页面。普通小表格仍按内容块协议处理。预筛报告单列任务范围排除数量，不混同采集失败率。

## 9. v3两阶段filter接入

统一入口为pipeline/cli.py dataset，单个YAML驱动预筛、后处理、裁片后筛、统计、校验与最终索引。
index-filtered/index-postprocessed/index-final分别保留来源、阶段状态和最终资格；最终索引必须经独立校验。
任一实际/核心裁片命中空白或纯色时，按用户最新要求剔除该视口全部裁片和切线监督，
正常其他视口独立保留；原始32例复核沿用原名单，显式展示被剔除项，不换样本。

## 10. 总体run与stop-after接续（已实现）

`run` 默认改为组件引擎，`--engine legacy` 才使用历史VLM/五层流程。
五个实际停止点为 filter、postprocess、final-filter、prepare-pack、pack。
filter不清框/切片；postprocess只生成候选，不执行裁片后筛、不发布trainable数据；
final-filter完成后筛、统计与独立校验；prepare-pack导出PNG/精简JSON/URL；pack压缩成tar.gz和metadata。
同阶段匹配的检查点可复用；跨阶段继续时重新核对原始文件并计算所需阶段结果。
来源、版本、页面选择、配置与产物指纹控制恢复，配置不匹配在修改索引前报错。
来源变化使发布索引失效，默认导出与压缩目录自动选择新后缀，已有成品不覆盖。
固定小样本已逐阶段停/续测通；现有3957视口全量结果用run --resume --stop-after pack验证通过，
最终索引、3856视口导出及1296页面/8个分片均复用，未重写成品。

## 12. 低覆盖率仅影响细节裁片训练

用户明确：覆盖率<20%时，只对该裁片加细节训练抛弃标记，不连带整页或其他裁片。
已增加detail-filter停止点，复用已验证v4生成结果，选择策略单独记录指纹。
选择索引的trainable清单排除低覆盖裁片，完整清单保留标记；整页切线文件完全不变。
导出JSON保留detail_training_eligible/detail_training_discarded/reason_codes与ID列表，
细节训练只消费eligible=true。即使一个视口所有细节裁片都退出，仍保留其整页原图和切线任务资格。
